[Cloudflare Managed OAuth](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/managed-oauth/) documents opaque tokens, RFC 8707 prerequisite, discovery, and refresh with policy reevaluation. It does **not** establish PKCE enforcement. [MCP authorization](https://modelcontextprotocol.io/specification/2025-06-18/basic/authorization) describes PKCE and resource indicators. [SDK source at npm gitHead](https://github.com/modelcontextprotocol/typescript-sdk/blob/3b73021a0a2272c0c04c3917bcdb03398b3ec63f/src/client/auth.ts) shows issuer-bound credential handling and OAuth flows. `S256_METADATA_ABSENT` means metadata did not advertise S256, not that PKCE is unsupported or unenforced. A PRM resource mismatch is `PRM_RESOURCE_MISMATCH` plus a sanitized URL, not a conclusion that Managed OAuth is unsupported: real app/resource mapping must be examined. No second OAuth stack is layered beneath Managed OAuth.

## Prepared code and evidence boundaries

- `spikes/f06/receiver.mjs`: validates Access assertion issuer/audience, RS256, `exp`, `iat` and `sub`; JWKS cache only. It hashes incoming PUT bytes, does not store them, and exports metadata-only stateless MCP. It sends the SHA-256 of UTF-8 `JSON.stringify(['forge-f06-identity-v1', issuer.origin, sub])` only in a response header to the local adapter, never in MCP tool output. This value is linkable, not anonymous; no raw JWT, sub or email is returned.
- `adapter.mjs`: `transfer_fixture(localPath, refreshOnly?)` reads only below absolute `F06_FIXTURE_ROOT`, streams fixture bytes and checks actual server hash and size. It writes one bounded `identity.json` fingerprint per profile/resource in the protected cache (0600), for operator-only comparison. Receipts expose paths, sizes and byte hashes, not identity. Cache and temporary evidence remain outside the project. Fixture root must be immutable and mode 0700 during runs: ancestor replacement races remain outside this spike's threat model; this is not production file handling.
- `oauth.mjs`: adapter-owned SDK OAuth and profile/resource cache, no harness credentials or CF admin credentials. `authPath` is `cached`, `refreshed` or `authorized`; successful observed refresh includes HTTP status. Failure includes bounded stage/code, actual HTTP status and only recognized OAuth error codes. `refreshOnly: true` attempts a real refresh and forbids all browser fallback; `invalid_grant` remains distinguishable from a new login. Concurrent authentication returns `AUTH_IN_PROGRESS`; cancellation passes the MCP signal to network and closes the callback listener. A challenge that does not name same-origin HTTPS PRM is refused.
- `negative-probe.mjs`: one-off operator-only wrong-verifier and wrong-resource experiments, on fresh **approved isolated test resources only**, never production. Wrong-verifier uses the first app and its independently observed `F06_AUTH_ISSUER`: `F06_NEGATIVE_APPROVED=yes F06_RESOURCE=<first-test-mcp-url> node negative-probe.mjs wrong-verifier`. Wrong-resource additionally requires separately approved second host, Worker and Managed OAuth app: set `F06_OTHER_APPROVED=yes`, `F06_OTHER_RESOURCE=<second-test-mcp-url>` and its independently observed `F06_OTHER_AUTH_ISSUER`, then run `wrong-resource`. The probe authenticates to the second app with its own OAuth client and verifies the token is accepted there, then makes a direct GET to the first with that token, without redirects, cookies or target reauthentication. A first-app 401/403 is rejection evidence; 2xx/405 is unexpected acceptance and other outcomes are inconclusive. A wrong-verifier token endpoint `invalid_grant` is rejection evidence; absence of S256 advertisement is a separate unproven gate. Distinguish resource granularity from per-app binding. Token and profile remain private; never log token bodies or callback URLs.
- `fixture.mjs` generates synthetic multi-MiB HTML plus relative CSS/SVG assets only at runtime. `wrangler.jsonc` is neutral, has no bindings, workers.dev or preview URLs; operator supplies exact isolated settings in a private config. `.dev.vars` is not a safe repository destination: keep all sensitive runtime config outside Git.

## Isolated client profiles — future run only

Create the following config in a protected scratch project, substituting actual nonsecret paths. `F06_RESOURCE` is `https://forge-f06-1fd930f85c34.unkillablecompanies.com/mcp`; `F06_FIXTURE_ROOT` is the absolute immutable fixture root; use distinct `F06_PROFILE` values for each harness. `F06_AUTH_ISSUER` is the exact HTTPS authorization-server issuer independently observed in the approved app's protected discovery metadata and verified by the operator; it is not the Access assertion issuer and must not be guessed. A mismatch fails closed before registration or token exchange. Set it for the negative probes as well.

The spike additionally requires the advertised authorization endpoint and token/registration POST endpoints to use the approved issuer's HTTPS origin without query parameters, and the metadata `issuer` to match the approved issuer. `AUTHORIZATION_ENDPOINT_ORIGIN_MISMATCH` and `OAUTH_ENDPOINT_ORIGIN_MISMATCH` are explicit client security boundaries, not evidence that Managed OAuth is unsupported; if real metadata uses another origin, stop for source/security review rather than relaxing the check silently.
